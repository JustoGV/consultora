### Data fetching & state
- **Server-side pagination:** `servicePaginated({ search, page, limit })` → returns `{ data, total, totalPages }`
- **Debounce:** `const ref = useRef<...>(null); ref.current = setTimeout(() => setPage(1), 300)`
- **Loading states:** `useState(true)` → set in try/finally blocks
- **Error handling:** `extractErrorMessage(error)` → spreads axios error message

### Forms & validation
- **Modal forms:** wrap inputs in `FormModal` container
- **Input masking:** numeric masking for DNI/CUIL/CUIT/phone/postal code (in `formUtils.ts`)
- **Validation:** on blur + Enter key (useFormKeyboard hook)
- **Submission:** prevent Enter in inputs; only submit buttons or Shift+Enter advances
- **Rollback:** `useContinuousCreate` for batch operations with atomic save

### Tables
- **Always use `DataTable`** — genérico, tipado, con skeleton/empty/pagination slots
- **Searchable:** `searchValue`, `onSearchChange` (parent applies debounce)
- **Numeric columns:** `numeric: true` → activates `tabular-nums`, right-aligns
- **Row click:** `onRowClick` handler
- **Example:**

## 7. Decisions & why

### Design system overhaul (UX-1)
**Why:** Brand identity needed. Moved from generic Admindek blue → teal (salud = confianza). Tokens defined in CSS; old pages adopt new identity WITHOUT touching JSX (remapped `blue-*` palette).

**Impact:** ~27 old pages got teal identity "for free"; DataTable + new components use semantic tokens from day one.

### Terceros vinculados at persona level (UX-17)
**Why:** Professionals (tutors, caregivers) link to person regardless of obra social affiliation (hospital/private patient scenarios). Separate from afiliación-level relationships.

**What:** New endpoint: GET/POST/DELETE `/personas/:id/profesionales`.

### Success confirmation overlay (UX-18)
**Why:** Corner toasts felt transient for critical ops (save afiliado). Centered, 1.4s overlay provides confidence.

**How:** `confirmSuccess('msg', ms)` in `src/lib/toast.tsx`; used on all create/update success.

### Multi-administradora strict isolation
**Why:** Compliance + data protection. ADMIN sees only own org; SUPERADMIN sees all. Enforced client-side in services (server enforces harder).

### Legacy → new wave (Ola 2)
**Why:** Not all pages rebuilt to new design system yet. Heroicons + ad-hoc styling still in older CRUD screens. Full migration planned; safe coexistence achieved via token remapping.

**Criteria for rebuild:** Lucide icons, DataTable, semantic tokens, no hardcoded blue.

## 10. Gotchas & landmines

- **API timeout:** 60s default (generous for backend startup; fail fast if backend is down)
- **JWT refresh:** No refresh token logic — token stored in localStorage, 401 redirects to login
- **Semáforo misuse:** Easy to accidentally use red/amber/green for non-alert contexts (validation, success) — **use severity.ts enforcer**
- **tabular-nums:** Forgotten on date/phone columns → layout shifts on digit changes
- **Severity badge variant mapping:** `severity.ts` is the source of truth; don't hardcode `variant="destructive"` for alerts
- **Responsive tables:** DataTable is desktop-first (good density); mobile scrolls horizontally (no collapse/accordion yet)
- **Administradora context:** New pages must get administradoraId from context (SUPERADMIN) or from auth user (ADMIN/USER)
- **Icon bloat:** Every old page + new component adds either Heroicons or Lucide; no deduplication yet
- **Form submission on Enter:** Keyboard flow allows Enter to advance fields; explicit Submit button must prevent default Enter
- **localStorage user state:** Persona data cached in localStorage in AuthContext; doesn't auto-sync if backend updates (page refresh needed)
- **Tailwind v4 CSS config:** No `tailwind.config.ts`; all config in `@theme` blocks in `globals.css` — easy to miss when adding utilities
